Problems I’ve diagnosed and fixed

Each lab starts with a customer-style symptom. I work out the cause, apply the fix, and check that it works.

Website timed out on EC2

Resolved
Symptom
The browser showed ERR_CONNECTION_TIMED_OUT.
Cause
The security group had no inbound rule for HTTP (port 80), so requests never reached the server.
Fix
Added an inbound HTTP rule and confirmed the page loaded.

Connection refused on EC2

Resolved
Symptom
The browser showed ERR_CONNECTION_REFUSED.
Cause
The firewall was open, but the NGINX service had stopped, so nothing was listening.
Fix
Connected with Session Manager (no SSH port), checked systemctl status nginx, and started the service again.

403 Forbidden on an S3 website

Resolved
Symptom
The S3 website endpoint returned 403 Forbidden.
Cause
Block public access was on, and no policy allowed visitors to read the files.
Fix
Turned off the block for this bucket and added a read-only bucket policy for the site’s files.

The rules I use to start a diagnosis

  • Timeout: the request is blocked before the server, so I check the network path.
  • Connection refused: the server answered but nothing is listening, so I check the service.
  • 403: the server answered and refused, so I check permissions.
  • 404: the server answered but the file is missing, so I check the file name and path.
